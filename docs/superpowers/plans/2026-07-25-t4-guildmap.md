# Tier 4 #1: Live guild map

Branch `feat/tier4`. Approved design: guildmates on the world map + minimap, ZONE-level for everyone by
default, exact live x/y as an explicit OPT-IN. Pins are our own frames on Blizzard's world map canvas; we
NEVER overwrite a Blizzard global (the raid-frame taint lesson). Two tasks: data/sync, then UI.

## Model
- `db.guildMapPrefs = { shareExact = false }` (opt-in for exact position; zone is always shared while the
  map feature is on).
- Local: on zone change and on a light throttle, read `C_Map.GetBestMapForUnit("player")` (mapID) and,
  when `shareExact`, `C_Map.GetPlayerMapPosition(mapID, "player")` (x,y in 0..1; nil inside instances,
  handle gracefully = zone-only). Broadcast a compact packet over `CommSystem` GUILD:
  `{ mapID, x, y, exact }` (x,y omitted/0 when not sharing exact). Never send inside an instance beyond
  the mapID.
- Receive (`GuildMap:HandlePosition(sender, data, channel)`): GUILD-only; identity = envelope sender
  (never payload); clamp x,y to [0,1] and mapID to a number; store
  `db.mapPeers[key] = { mapID, x, y, exact, class, level, ts }`. class/level come from the roster/member
  DB, not the payload. TTL-prune (e.g. 300s) so stale peers drop.
- `GuildMap:GetPeers(now)` -> sorted list of online guildmates with a known position, for the UI list.
  Pure aggregate over a fake-able store; unit tested.

## Task 1: data + sync (`Modules/GuildMap.lua`, `Modules/CommSystem.lua`, `.toc`, `Core/Core.lua`)
- New module: prefs, local position read (Compat-guarded C_Map), broadcast on `ZONE_CHANGED_NEW_AREA` /
  `PLAYER_ENTERING_WORLD` + a throttle, plus a HandleRequest answer so a guildmate logging in converges.
  `HandlePosition` receiver, `GetPeers` aggregate, pure helpers (`_ClampPos`, `_SortPeers`, TTL prune)
  with self tests.
- `CommSystem`: new `MAP_POS = "MP"` type, a dispatch branch passing `(sender, data, channel)` exactly
  like RECRUIT_STATS/RI, and a HandleRequest send. Do NOT touch other message types.
- `.toc` + `InitModules` wiring. luacheck 0/0. No UI in this task.
- Security carries over: GUILD-only, envelope-bound identity, clamped payload. Position is opt-in for the
  exact form; document it.

## Task 2: UI (`UI/GuildMap.lua`, minimap button entry, `Core/Commands.lua`, `Locales/*`)
- `/gos map` and a minimap-button menu entry open the map. The map view = pins on Blizzard's
  `WorldMapFrame` canvas (our textures, parented to the canvas, positioned by x/y for peers on the
  currently viewed map; zone-center marker when only zone is known) + a draggable list overlay
  (name/class/zone, click centers the map on that peer's zone) + a small "share my live position"
  checkbox bound to `guildMapPrefs.shareExact`. Minimap: class-colored dots for guildmates in the
  player's current zone.
- v1 scope: pins for peers on the SAME map the user is viewing (cross-map coordinate translation is not
  reliable in BCC, so other-map peers appear in the LIST with click-to-navigate, not as pins). State this
  limit in the report; do not silently drop them.
- Taint-safe: only our own frames, parented to the map; hooksecurefunc if a Blizzard hook is needed
  (e.g. WorldMapFrame OnShow/OnMapChanged), never a global overwrite. Design round already approved; this
  is a new screen so follow the mockup.

## Self review
- Zone-default / exact-opt-in honored; exact never sent unless `shareExact`. Instances never leak coords.
- Envelope-bound, GUILD-only, clamped: a peer cannot forge another's position or break the UI.
- No Blizzard global overwrite anywhere (taint-safe).
